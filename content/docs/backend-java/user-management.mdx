The user management module provides REST endpoints for user profile operations including viewing, updating, batch lookups, and soft account deletion. All endpoints require JWT authentication.

## UserController Endpoints

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/api/v1/users/me` | GET | Current user profile |
| `/api/v1/users/batch` | GET | Batch lookup by multiple user IDs |
| `/api/v1/users/me` | PATCH | Update profile (name, phone, email) |
| `/api/v1/users/me/password` | PATCH | Change password |
| `/api/v1/users/me/login-identifiers` | PATCH | Update email or phone number |
| `/api/v1/users/me` | DELETE | Soft delete account |

<Callout type="info">
The `/api/v1/users/batch` endpoint requires JWT authentication and supports max 100 user IDs per request via query parameter `ids=uuid1,uuid2,...`.
</Callout>

## UserEntity Model

```java
@Entity
@Table(name = "users")
public class UserEntity {
    @Id
    @GeneratedValue
    @UuidGenerator
    @Column(name = "user_id")
    private UUID userId;

    @Column(name = "username", nullable = false, unique = true)
    private String username;

    @Column(name = "display_name", nullable = false)
    private String displayName;

    @Column(name = "email", unique = true)
    private String email;

    @Column(name = "phone_number", unique = true)
    private String phoneNumber;

    @Column(name = "password_hash")
    private String passwordHash;

    @Enumerated(EnumType.STRING)
    @Column(name = "role", nullable = false)
    private Role role;

    @Column(name = "google_sub", unique = true)
    private String googleSub;

    @Column(name = "created_at", nullable = false)
    private Instant createdAt;

    @Column(name = "updated_at", nullable = false)
    private Instant updatedAt;

    @Column(name = "deleted_at")
    private Instant deletedAt;
}
```

### Field Descriptions

| Field | Type | Description | Constraints |
|-------|------|-------------|-------------|
| `userId` | UUID | Primary key | Auto-generated, UUID v4 |
| `username` | String | Unique login identifier | Non-null, unique, case-sensitive |
| `displayName` | String | Visible user name | Non-null, can contain spaces |
| `email` | String | Email address | Unique, nullable |
| `phoneNumber` | String | Phone number | Unique, nullable |
| `passwordHash` | String | BCrypt hashed password | Nullable (SSO-only users) |
| `role` | Role enum | User authority level | PELAJAR or ADMIN |
| `googleSub` | String | Google authentication subject | Unique, nullable |
| `createdAt` | Instant | Account creation timestamp | Auto-set on insert |
| `updatedAt` | Instant | Last update timestamp | Auto-set on update |
| `deletedAt` | Instant | Soft delete timestamp | NULL = active, Instant = deleted |

## Role Enum

Users have one of two roles:

```java
public enum Role {
    PELAJAR,  // Student - default for regular users
    ADMIN     // Administrator - full access
}
```

## UserRepository JPA Queries

The repository provides these custom queries:

```java
// Find by identifier with deleted filter
findByEmailAndDeletedAtIsNull(String email)
findByPhoneNumberAndDeletedAtIsNull(String phoneNumber)
findByUsernameAndDeletedAtIsNull(String username)

// Find by identifier including soft-deleted
findByEmail(String email)
findByPhoneNumber(String phoneNumber)
findByUsername(String username)

// Google OAuth
findByGoogleSub(String googleSub)

// Batch lookup
findAllByUserIdIn(List<UUID> userIds)
```

<Callout type="warning">
The `deletedAt` field is checked with `IS NULL` for active queries and explicitly checked for soft-deleted users. This prevents soft-deleted users from logging in or appearing in lookups.
</Callout>

## Profile Update Constraints

### Update Profile (`PATCH /api/v1/users/me`)
- `displayName`: String, non-null
- `phoneNumber`: String, unique, optional
- `email`: String, unique, optional

### Change Password (`PATCH /api/v1/users/me/password`)
- `oldPassword`: Current password for verification
- `newPassword`: Minimum 8 characters
- Only users with `passwordHash` (non-SSO) can change password

### Update Login Identifiers (`PATCH /api/v1/users/me/login-identifiers`)
- `email`: New email, must be unique
- `phoneNumber`: New phone, must be unique
- SSO-only users (null passwordHash) can update identifiers

## Soft Delete Behavior

When a user soft-deletes:
1. `deleted_at` set to current `Instant`
2. All queries filter out with `deletedAt IS NULL`
3. User cannot login (active query returns missing)
4. Google OAuth SSO users can still be soft-deleted
5. Deleted flag persists for audit trail
